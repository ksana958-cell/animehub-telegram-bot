# AnimeHUB bot — безопасное развёртывание

## 1. Сразу отозвать скомпрометированный токен

Токен, который ранее находился в `animehub_bot.py`, следует считать скомпрометированным навсегда. В @BotFather отзовите его и выпустите новый. Не вставляйте новый токен в Git, `.env.example`, README, скриншоты или сообщения.

## 2. Переменные окружения хостинга

Обязательно задайте:

- `BOT_TOKEN` — новый токен из @BotFather.
- `CHANNEL_USERNAME` — например `@AnimeHUB_Dream`.
- `ROOT_ADMIN_IDS` — Telegram ID корневых администраторов через запятую.

Рекомендуется задать новые коды доступа:

- `ACCESS_CODE_VIP`
- `ACCESS_CODE_FRIEND`

Используйте длинные случайные значения (минимум 24–32 случайных символа). Старые коды доступа, которые когда-либо были в Git, больше не используйте.

## 3. Git

Файл `.gitignore` уже исключает `.env`, `bot_data.json`, бэкапы и логи. Если `bot_data.json` или `.env` когда-либо уже были добавлены в Git, одного `.gitignore` недостаточно — удалите их из индекса, не удаляя локальный файл:

```bash
git rm --cached .env bot_data.json
```

Если файла нет в индексе, Git может сообщить об ошибке — это нормально.

Старый Telegram-токен уже нужно отозвать. При необходимости полностью удалить его из истории репозитория используйте `git filter-repo` или BFG и затем принудительно перепишите удалённую историю. После переписывания истории всем участникам лучше сделать свежий clone.

## 4. Установка

```bash
pip install -r requirements.txt
```

В проекте зафиксирована версия:

```text
python-telegram-bot==22.6
```

## 5. Права бота в Telegram

Оставляйте боту только те права администратора канала, которые реально нужны. Для текущего кода это обычно публикация/редактирование сообщений; не выдавайте дополнительные права без необходимости.

## 6. Что изменено в коде

- `BOT_TOKEN` берётся только из переменной окружения и проверяется при старте.
- Старые коды доступа удалены из исходника; новые берутся из env.
- Сравнение кодов выполняется через `secrets.compare_digest`.
- Friend-invite создаётся через `secrets.token_urlsafe`, а в JSON хранится только SHA-256 токена.
- Root-admin нельзя заблокировать командой `/ban_user`.
- Пользовательский текст в HTML-сообщениях экранируется.
- Внутренние исключения больше не отправляются пользователям; они попадают только в лог.
- Логи автоматически маскируют строки, похожие на Telegram bot token.
- `bot_data.json` и его резервные копии получают права `0600`, где это поддерживается ОС.
- Обработка updates оставлена последовательной, что безопаснее для `ConversationHandler` и файлового JSON-хранилища.
- По умолчанию старые pending updates удаляются при рестарте (`DROP_PENDING_UPDATES=true`).

## 7. После деплоя

1. Закоммитьте `animehub_bot.py`, `.gitignore`, `requirements.txt`, `.env.example` и этот файл.
2. Не коммитьте `.env` и `bot_data.json`.
3. В панели хостинга вставьте новый `BOT_TOKEN` и новые access-коды.
4. Нажмите «Обновить из Git» / «Пересобрать».
5. Проверьте `/start`, `/help`, `/admin_list` и одну тестовую публикацию в канал.
6. В @BotFather и настройках канала проверьте, что неизвестных администраторов и интеграций нет.

## Важно

Ни один код не даёт абсолютной защиты от «взлома». Telegram bot token — bearer-secret: любой, кто получил актуальный токен, может обращаться к Bot API от имени бота в пределах его Telegram-прав. Поэтому ключевые меры — немедленная ротация утёкшего токена, хранение нового токена только в secrets/env, минимальные права бота и отсутствие секретов в Git/логах.
